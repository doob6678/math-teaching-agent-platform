> 页面图片服务和控制器对教材页面图像进行资源访问和展示支持。

# 教材页面图片资源服务

教材页面图片资源服务位于 Java 后端 `resources` 模块，负责将教材处理产物目录中的页面图像映射为稳定的后端访问地址，并通过 HTTP 流式返回给前端或教学流程使用。

服务不向客户端暴露 `processed_books` 的绝对路径。调用方只需要使用教材文档标识和页码：

```text
GET /api/resources/textbooks/{docId}/pages/{pageNo}/image
```

后端再根据教材目录、页面图片索引和受控路径解析结果定位实际文件。

## 模块职责

主要职责包括：

- 从配置中确定教材处理产物根目录。
- 读取 `catalog.jsonl` 和页面图片索引文件。
- 根据 `docId` 与 `pageNo` 查找页面图片元数据。
- 解析教材目录，兼容跨平台或不可移植的目录路径。
- 校验实际图片路径必须位于配置的 `processed_books` 根目录内。
- 推断响应 MIME 类型并以内联方式返回图片。
- 将非法参数、缺失索引、目录不存在或图片文件不可用统一转换为 HTTP 404。

核心实现位于 `TextbookPageImageService`，HTTP 入口位于 `TextbookPageImageController`。

## 调用链

```mermaid
flowchart TD
    A[客户端或前端] -->|GET /api/resources/textbooks/{docId}/pages/{pageNo}/image| B[TextbookPageImageController]
    B --> C[TextbookResourceProperties.processedBooksRoot]
    B --> D[TextbookPageImageService.openPageImage]
    D --> E[读取 _page_image_index/manifest.json]
    D --> F{缓存索引仍匹配 fingerprint?}
    F -->|是| G[复用 CachedPageImageIndex]
    F -->|否| H[读取 catalog.jsonl]
    H --> I[读取 _page_image_index/metadata.jsonl]
    I --> G
    G --> J[按 docId#pageNo 查找页面元数据]
    J --> K[TextbookBookRootResolver.resolve]
    K --> L[解析 source_page_image 或 page_image_path]
    L --> M{路径位于 processed_books 根目录?}
    M -->|否| N[抛出 IllegalArgumentException]
    M -->|是| O[FileSystemResource]
    O --> P[推断 MIME 类型并设置 inline 文件名]
    P --> Q[ResponseEntity<Resource]]
    N --> R[HTTP 404]
```

关键节点如下：

- `TextbookPageImageController` 只负责接收路径参数、调用服务并构造 HTTP 响应。
- `TextbookPageImageService` 负责索引加载、元数据查找、路径解析和资源封装。
- `TextbookBookRootResolver` 负责将目录记录转换为当前部署环境中的安全目录。
- `FileSystemResource` 将最终的本地文件交给 Spring 进行响应体流式读取。

## 请求与响应

控制器映射在：

```text
/api/resources/textbooks/{docId}/pages/{pageNo}/image
```

调用服务时传入：

- `processedBooksRoot`：配置的教材处理产物根目录。
- `docId`：教材文档标识。
- `pageNo`：页面编号。

服务成功后返回 `VisibleTextbookPageImage`，其中包含：

- `docId`
- `pageNo`
- 稳定图片 URL
- MIME 类型
- 文件名
- Spring `Resource`

控制器随后构造 `ResponseEntity<Resource>`：

- HTTP 状态为 `200 OK`。
- `Content-Type` 由文件探测结果决定。
- `Content-Disposition` 使用 `inline`，允许浏览器直接展示图片。
- 响应体为实际文件资源。

服务也提供 `pageImageUri` 方法，用于根据文档标识和页码生成稳定 URL，但该方法只生成地址，不读取文件。

## 索引加载与缓存

页面图片服务依赖以下处理产物：

```text
{processedBooksRoot}/catalog.jsonl
{processedBooksRoot}/_page_image_index/manifest.json
{processedBooksRoot}/_page_image_index/metadata.jsonl
```

加载过程如下：

1. 将配置的根目录转换为绝对路径并规范化。
2. 读取 `manifest.json` 中的 `fingerprint`。
3. 如果内存缓存中的根目录和 fingerprint 均一致，则复用 `CachedPageImageIndex`。
4. 否则重新读取教材目录和页面图片元数据。
5. 将目录构建为 `docId -> TextbookCatalogItem`。
6. 将页面元数据构建为 `docId#pageNo -> PageImageMetadata`。
7. 使用不可变 Map 保存新的缓存索引。

页面元数据支持的字段包括：

```json
{
  "doc_id": "example-book",
  "page_no": 12,
  "source_page_image": "pages/page-0012.png",
  "page_image_path": "/path/to/page-0012.png"
}
```

JSONL 读取会跳过空行，并移除行首 UTF-8 BOM，以兼容由 Windows 工具生成的文件。未知 JSON 字段会被忽略。

缓存是单实例内存缓存，使用 `volatile` 字段发布新的索引。缓存失效依赖 manifest fingerprint 变化；因此重新生成页面图片索引时，应同步更新 manifest 中的 fingerprint。

## 页面定位与路径安全

页面查找首先通过规范化后的 `docId` 和正数页码生成键：

```text
docId#pageNo
```

如果没有对应元数据，服务直接报告页面图片不存在。

找到页面元数据后，服务先通过 `TextbookBookRootResolver` 解析教材目录：

1. 如果 catalog 中的 `book_root` 是有效路径，并且位于当前 `processedBooksRoot` 内，则优先使用该路径。
2. 如果 catalog 路径来自其他操作系统、无法解析，或不在当前根目录下，则回退到：
   ```text
   processedBooksRoot/{docId}
   ```
3. 回退路径必须位于根目录下，且 `docId` 必须是单一普通路径段。
4. `docId` 不允许是绝对路径、`.`、`..`，也不允许包含 `/` 或 `\`。
5. 目标教材目录必须实际存在。

页面图片路径解析也包含根目录约束：

- 优先解析元数据中的 `source_page_image`，相对于教材目录进行规范化。
- 若该字段为空，则尝试使用 `page_image_path`。
- 两种路径都必须位于 `processedBooksRoot` 内。
- 如果路径越界、格式非法或无法定位，则拒绝访问。
- 最终路径还必须满足 `Files.isRegularFile`，目录、软链接解析后的越界路径或不存在文件都不会被返回。

这种设计使客户端只能通过稳定的 `docId` 和页码访问资源，不能直接提交服务器本地绝对路径。

## 参数校验与错误状态

服务层的主要校验包括：

| 条件 | 行为 |
| --- | --- |
| `docId` 为空或仅包含空白 | 抛出参数错误 |
| `pageNo <= 0` | 抛出参数错误 |
| 页面索引不存在 | 抛出页面不存在错误 |
| catalog 中没有对应 `docId` | 抛出教材目录不存在错误 |
| 教材目录不存在 | 抛出目录不存在错误 |
| 页面路径不在根目录内 | 抛出非法路径错误 |
| 页面文件不是普通文件 | 抛出文件不可用错误 |
| manifest、catalog 或 metadata 读取失败 | 抛出 `IllegalStateException` |

控制器捕获服务抛出的 `IllegalArgumentException`，统一转换为：

```text
HTTP 404 Not Found
Textbook page image not found
```

索引文件读取失败属于服务运行状态或部署数据问题，服务不会将其伪装成普通的页面缺失。

MIME 类型通过 `Files.probeContentType` 探测。探测失败或结果为空时，回退为：

```text
application/octet-stream
```

文件名优先使用实际图片文件名；如果无法取得文件名，则使用：

```text
{docId}-page-{pageNo}.bin
```

## 配置边界

`TextbookResourceProperties` 负责提供教材处理产物根目录。

标准配置项为：

```text
MATH_AGENT_PROCESSED_BOOKS_ROOT
```

从 Spring 环境读取时，还支持：

```text
math-agent.resources.processed-books-root
```

Spring 属性优先，缺失时回退到系统环境变量。配置缺失会在创建属性对象时抛出异常；配置值会被转换为绝对路径并规范化。

该配置是页面图片服务的运行前提，部署时必须保证：

- 根目录存在并可被后端进程读取。
- 根目录下存在教材目录和目录索引。
- `_page_image_index/manifest.json` 可读取。
- `_page_image_index/metadata.jsonl` 可读取。
- 页面元数据引用的图片文件仍然存在。

## 与教材资源摘要的关系

同一资源模块还提供教材资源摘要接口：

```text
GET /api/resources/textbooks/summary
```

该接口由 `TextbookResourceController` 调用 `TextbookResourceService`，使用相同的 `processedBooksRoot` 配置。它用于资源概览，不参与单页图片文件的定位和流式返回。页面图片访问的核心入口仍是 `TextbookPageImageController`。

## 扩展点

当前实现适合单机或共享文件系统上的教材页面资源访问，主要扩展点包括：

- **索引缓存策略**：可将单实例 `volatile` 缓存扩展为按根目录维护的缓存，或引入显式刷新与过期策略。
- **资源类型支持**：可在现有页面图片元数据基础上扩展缩略图、裁剪图或不同分辨率版本，但每种资源仍应经过根目录边界校验。
- **内容类型策略**：可增加明确的图片格式白名单，避免完全依赖文件系统 MIME 探测。
- **访问控制**：当前控制器注释和实现体现的是公开资源端点；若业务要求教材可见性或用户权限校验，应在控制器前置层或资源服务边界增加授权判断。
- **缓存响应**：可根据 manifest fingerprint 或页面元数据生成 HTTP 缓存标识，减少重复传输。
- **存储后端替换**：`VisibleTextbookPageImage` 以 Spring `Resource` 表达返回资源，未来可替换为对象存储资源或其他 `Resource` 实现，同时保留稳定的 doc/page URL 合同。
