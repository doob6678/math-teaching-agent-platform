# 高考题库入库与 Luna 治理

本实现以 `paper_type` 策略表驱动一条通用流程：全量解析、跨文件配对、去重/变式判定、人工审核、发布索引和讲义验证。公开来源由后端结构化格式化，严禁将 run ID、文件哈希、资产 ID、路径、模型 ID 或 token 输出到讲义、前端或 MCP。

## 发布与模型边界

Luna（`gpt-5.6-luna`）是本轮唯一可执行实验模型。无官方答案时，它只能形成待审草稿；只有人工确认后才可标记为 `HUMAN_APPROVED_MODEL_ASSISTED` 并写入 canonical 层。Embedding 继续使用既有本地 `local_bge_embedding`，仅用于候选召回，不能决定合并或发布。

## 数据与恢复

`import_run` 记录处理和验证的独立状态。文件以 `runId + sourceFileHash` 幂等，来源出现以文件、页码、区域和题号定位；改变的文件建立新版本，旧证据永不覆盖。所有拆分、合并、审核和发布均追加审计行。

## 当前边界

核心契约与数据库审计 Schema 已落地。真实切题、配对、Golden、Luna 分布和 PDF 验收必须以用户指定的真题文件为输入；在输入缺失时不生成虚构报告或成功结论。
