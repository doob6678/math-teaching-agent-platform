# 高考语料入库链路：问题与系统瓶颈记录（2026-08-31）

本文记录 2026-08-31 跨页题图修复 + 12 卷全量重发布/重入库过程中实测发现的问题与瓶颈，
作为后续优化的依据。数据均为当日真实运行的观测值。

## 一、当天修复的两个链路缺陷

1. **跨页题图绑定缺失**：题号锚点只在同页匹配，解析卷续页上的题图（无印刷题号）被
   fail-closed 丢弃。2022 新高考Ⅰ卷 19 题两图只发布一图即此缺陷。修复为全文阅读顺序
   最近前置锚点 + 行首题号正则收紧（排除“共 7 种”“A. 1”“1.6×10⁹m³”类假锚点）。
2. **题图统一文末追加**：发布时不看语义位置。修复为按来源页 + bbox.top/页高比例插回
   “如图”类段落之后（textSegments 页级正文块对齐），无法定位保底文末追加。

修复后 12 卷题图资产 95 张，逐题 md 内 99 处题图引用全部就位（含跨页合并产生的资产）。
旧资产目录已被重建覆盖，全量旧计数无基线可查；唯一可对照的 2022 新高考Ⅰ卷为 4→8 张。

## 二、环境层（最危险的一类：静默错算）

### 2.1 paddle cu126 构建 × RTX 5060（sm_120）静默返回 0

- 现象：GPU 上所有计算内核（add/conv/sum/matmul）结果恒为 0 或输入回显；H2D/D2H 拷贝
  正常；`paddle.utils.run_check()` 照样通过；OCR 推理 exit 0 但输出空框。
- 根因：Windows 驱动已升到 596.36（CUDA 13.2），paddlepaddle-gpu 3.3.1 的 cu126 构建没有
  Blackwell 内核且 PTX JIT 静默失败。torch 2.13 cu130（ai-worker 容器）在同一 GPU 正常，
  证明驱动栈无问题。
- 修复：同版本号换装 **cu129 构建**（`--force-reinstall --no-deps`，官方源
  `https://www.paddlepaddle.org.cn/packages/stable/cu129/`），paddleocr 3.7.0 /
  paddlex 3.7.2 不动。
- 教训：**GPU 环境校验必须验证数值正确性，不能只验证“不报错”**。脚本里 `require_gpu`
  当时验证了 1+1=2 的数值，这个设计是对的——它拦下了静默错算直接进 OCR 的路径。

### 2.2 依赖漂移连环雷（同一天连续踩中）

- paddlex 3.7+ 把 `create_predictor` 的 `model_dir` 改成 keyword-only，位置传参直接
  TypeError（旧脚本按旧签名写）。
- 脚本 `count_pages` 用裸 `python3` 调 pypdf：在 GPU venv 激活状态下解析到 venv 解释器
  （无 pypdf），系统 python3 才有。已改 `/usr/bin/python3` 绝对路径。
- 教训：WSL GPU venv 与系统 python 的依赖是两套，跨解释器调用必须绝对路径；脚本对
  paddlex 的调用要用最新签名并注释版本前提。

### 2.3 Windows/WSL 文件层

- `/mnt/c`（DrvFs/9P）上 `shutil.rmtree` 对目录壳报 EPERM；Git Bash 删被句柄占用的目录
  报 "Device or resource busy"（本机文件索引/监视器常见）。`--replace` 已实现“整删失败
  退化为清空子项”的 `clear_target` 兜底。
- 大量小文件 IO（OCR 逐行裁剪、证据 JSON）走 /mnt/c 明显慢于 WSL 原生 fs；本次未迁移，
  后续批量重建可考虑 scratch 放 `~/`。

## 三、视觉转写层（Terra）

### 3.1 120s 读超时对高密度页不足 → 整 run fail-closed 中止

- 实测：207 页中 8 页（2022Ⅰ p11/p6/p17/p19、2023Ⅰ p5/p24、2023Ⅱ p5、2024Ⅰ p2）在
  120s × 3 次重试内未返回，首轮 run 在页任务阶段整体中止（这是设计上的 fail-closed）。
- 放大到 300s 后单页重试全部成功，代价是串行补页约 18 分钟。
- **恢复机制的价值被验证**：200 页成功证据落盘后，补齐缺失页 + `--finalize-run-id`
  即可完成发布/嵌入/入库，避免了重花 ~70 万 token 的全量重转。补页目前是一次性驱动
  （`.local-run/retry_missing_pages.py`），建议产品化为 runner 的 `--retry-missing` 选项。

### 3.2 结构化漏项（比超时更隐蔽）

- 实测：2023Ⅱ 第 5 页 Terra 的 `pageText` 完整覆盖整页（以页脚收尾），但 `questions[]`
  只结构化出第 7 题，第 9 题整题丢失——pageText 非空这一唯一门禁拦不住它。
- 同页还出现题干里混入元描述（“页面下部可见两种解法，其中第二种解法在本页末中断”）。
- 处置：删除该页证据重转一次后恢复。**建议**：发布前加“题号连续性告警”（1..N 缺号、
  多卷对比缺失题号），把这类漏项从静默变成显式退出码。

## 四、嵌入与向量层（回答“embedding 是不是有点慢”：是，且缺观测）

- finalize 阶段（发布 + 嵌入 + Milvus + 召回自检）约 7 分钟，其中大头是嵌入 260 条记录：
  248 条逐题文本 + 12 条**全文文档**（每条数千字）。批大小 EMBEDDING_BATCH_SIZE 分批，
  但长文本批单次请求接近/超过 120s（首轮就出现过一次 embed ReadTimeout）。
- 嵌入是 finalize 的主导尾延迟，但 **run 报告不记录嵌入阶段耗时/批次数**，只能靠
  墙钟推断。建议：report 增加 `embedding: {batchCount, elapsedMs, textCount}`。
- Milvus 侧（FLAT、千级向量）upsert 3 批 + flush + 召回自检秒级完成，不是瓶颈。

## 五、数据流层（本轮暴露的存量缺陷）

- **资产按题号整卷挂载 + 同号续页合并直接拼接**：`recognized_questions` 给每个带题号
  记录挂该题号的全部资产，两页同号记录合并时 `prev + current` 把同一份资产拼两遍。
  修复前资产少未暴露；12 卷全量后 2022Ⅱ Q3 出现 4 资产（2 张图各重复一次）。已修：
  合并时按 `assetId` 去重。
- 同类盘点结论：题图绑定以“印刷题号”为锚是权威语义；转写题号与 OCR 题号偶有不一致
  （collision repair 已有处理），孤儿资产（绑定题号未发布）当前静默丢弃，建议并入
  上面第三.3.2 的连续性告警。

## 七、设计债：用魔法字符串/特例归一化对抗模型输出（2026-08-31 老板评审指出）

这一节记录同一类根因的四处代码：**下游用启发式猜测去“猜”上游模型的输出形态**。
正确的方向是反过来——把输出形态写成契约（结构化字段/明确格式要求），让模型按契约
产出，下游只做校验不做猜测。

### 7.1 `_normalize_locator_text` 的特殊字形归一化表（特例补丁）

- 现状：题干定位前对文本做 NFKC + maketrans 字形表归一（²→^2、₁→_1、−→-、—→-），
  是为“转写里用了 ² 而页文用了 ^2”这类个案逐个打的补丁，每遇新字形就要再加一行，
  补丁集合永不完备。
- 正确方向：**在转写 prompt/契约里明确告诉模型“应该写成什么形式、不要什么形式”**——
  数学表达式统一用 LaTeX/ASCII 形式（x^2、a_1、减号用 -），禁止上标/下标 Unicode 字形；
  下游归一化只保留 NFKC 这类标准等价折叠，删除逐字形映射表。

### 7.2 `segment.find("【答案】")` 魔法标记切分（无泛用性）

- 现状：解析卷答案段靠在文本里搜 `【答案】`、`【解析】` 这类印刷标记定位并切分，
  标记变体（空格、全半角、漏转写）一出现就静默失效。
- 正确方向：切分依据应是**结构化字段**（让 Terra 在 questions[] 里输出
  `stem`/`answer`/`analysis` 字段边界），或至少以“下一题题号行”为边界推断；
  印刷标记只能作为兜底信号之一，不能当唯一权威。

### 7.3 同族问题盘点（本轮顺手发现的同类启发式）

- 语义插图定位的“如图”触发词表（`如图|见图|如下图|如图所示`）：词表枚举式匹配，
  换一种表述（“见下图”“图示”）就 miss。应让转写模型在结构化输出里标注
  **插图锚点句**（哪个段落引用了哪张图），发布层只消费锚点。
- 跨页拼接按字面 `\n\n` 切 `textSegments` 再数块数对齐 solution 页数：靠“块数恰好
  等于页数”的巧合成立，任何一段内部含空行就错位。应让 textSegments 自带稳定 ID，
  拼接/拆分按 ID 引用而不是按分隔符重数。

### 7.4 `reconcile_question_numbers_from_page_text` 接线实测回归（已回滚）

- 背景：为修复 2023Ⅱ 第 9 题（圆锥题）被 Terra 视觉误标成 7（与真 7 题在去重时互相
  吞并），把“按页文印刷题号重对齐每条题干”的 reconcile 接进了发布主流程。
- 实测（真实证据干跑）：**修不了目标案例，还引入新回归**——
  - 圆锥题修不了：该页 pageText 只转写了分析段，**根本没转写题干行**，签名定位失败；
    题号回退也找不到 “7.” 行 → 记录保持 7。
  - 反而误伤 3 条正确记录（2022Ⅰ #6、2024Ⅰ解析 #10、甲解析 #22）：签名取题干首行
    **首现匹配**，命中了页文中更早的相似文字（同句式题干/分析复述），读到的“上方最近
    印刷题号”是别题的号 → 记录被改号后与既有号碰撞、去重吞并 → 全量从 248 掉到 235。
- 处置：**已回滚接线**（函数保留但不在主流程调用，配套单元测试保留为函数级契约），
  finalize 重跑恢复 248 题基线。2023Ⅱ Q9 缺失作为已知缺口记录在案（该题正文仍存在于
  全文文档向量中，只是无逐题向量）。
- 结论与 7.1/7.2 同源：**事后按印刷文本反推对齐这条路在真实数据上不可靠**；正确解法
  是 3.2 的题号连续性告警（把漏项/误标变成显式退出码）+ 转写契约里要求模型输出与
  印刷题号一致的 number 字段，而不是发布层静默改号。

## 八、v2 结构化转写协议：设计债的彻底偿还（2026-09-01 老板令，实施 scripts/wsl/run_gaokao_structured_ingestion.py）

第七节的 7.5 是对旧管子的**打补丁**（通用折叠、结构类小节标题——仍是"下游猜上游"）；
老板 2026-09-01 评审指出补丁思路本身就是错的："不管什么题、多少道、数字怎么列、有没有
答案解析，都不用正则匹配，而是按定义好的格式让 LLM 输出结构"，并点名两个具体病灶：
①解析卷转写里打印"19."与结构题号重复堆叠；②一题双图（2022Ⅰ q19）时按"图"字+几何
比例猜插图位置，泛化不足。v2 据此把**提示词变成唯一结构契约**，管线只消费协议字段。

### 8.1 协议定义（vision_request 提示词，JSON 输出）

每题记录：`number`（纯数字，禁止 "19."/"第19题"）、`stem`（不含题号，题图引用处按阅读
顺序嵌 `[[FIGUREn]]` 占位 token）、`answer`/`analysis`（印刷原文，无则空串=正常分支，
禁止题号与小节标签前缀）、`figureCount`（标记数自校验）、`parentNumber`（无号片段声明
归属题号）、`continuesToNextPage`/`latex`/`confidence` 沿用；`pageText` 仍发布为全文页，
但**不再参与任何结构反推**。questions 数组顺序=版面阅读顺序（契约明令）。

### 8.2 管线规则（确定性装配，零正文正则）

- 装配模板 `stem + 【答案】answer + 【解析】analysis`（`\n\n` 连接），题号只出现在发布
  标题——"19题/19."重复从结构上消灭；latex 不再拼正文尾行（旧管线跨页合并后公式重复
  堆叠成裸行的实测缺陷随之消失）。
- 题图绑定：资产按 `(pageNumber, bboxPixels.top)` 有序，第 k 个 `[[FIGUREk]]` 替换为第 k
  张图；标记允许落 stem/answer/analysis 任一字段（2022Ⅰ q19 图2 的"如图"在【小问2详解】
