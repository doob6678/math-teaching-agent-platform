# 全局问题修复计划与设计方案

> 本文只记录本轮全局问题修复的实施边界和设计约束；不读取、不复制 `全局问题.txt` 的内容。

## 目标

在不干扰其他开发者并行修改的前提下，优先消除会造成越权、跨租户、后台误启动、数据迁移漂移、基础设施弱认证和资源耗尽的根因，并为剩余功能问题建立可重复的真实回归入口。

## 明确边界

- `localPath` 是本地开发能力，按要求保留，不增加生产目录收敛规则。
- 不恢复 capability token；请求身份只来自后端解析的用户会话/服务主体，权限由角色、租户和资源所有权决定。
- 登录用户的限流主体使用后端解析的用户主体；匿名请求仅使用匿名主体作为兜底，不把客户端提供的设备标识当作认证凭据。
- 不修改 IP、DNS 或工作区外项目。
- 不清理、回滚或覆盖其他开发者已有改动。

## 设计方案

### 1. 身份、租户和资源权限

公开注册不接受客户端租户归属；租户由本地默认租户、邀请或已认证管理员上下文决定。所有教师资源读取、写入、归档、同步和资产访问均经过同一租户/角色/资源所有权策略。权限字段保留可变 scope；除 `TEACHER_PRIVATE` 外的共享 scope 对同租户学生可读，空 scope 默认 `TENANT_PUBLIC`。

### 2. 后台任务启动边界

RabbitMQ 自定义监听器工厂显式读取统一启停配置；关闭时工厂和调度器都不得启动。Feishu scheduler 默认关闭，空资源选择不解释为“全部”，后台任务必须有明确资源范围和服务主体。

### 3. 数据库和依赖就绪状态

Flyway 启动时执行版本和 checksum 校验，禁止以忽略缺失迁移的方式掩盖漂移。健康检查拆分存活和就绪，并真实检查 MySQL、Redis、RabbitMQ、Milvus、Worker 与迁移状态。

### 4. 输入、上传和资源生命周期

上传 ZIP 使用流式大小、文件数、单文件、目录深度和异常清理限制。成功归档和失败过期 staging 统一由生命周期清理器处理。此设计只约束上传产生的托管目录，不改变本地开发 `localPath` 语义。

### 5. AI 取消与并发

所有模型入口经过共享并发边界；SSE 断开向下游传播取消信号，释放请求、线程、租约和临时资源。并发限制按模型/GPU/租户/优先级记录指标。

### 6. 可验证性

先运行真实依赖上的针对性测试，再运行后端、前端和 Python 验证。每个修复必须有对应的回归证据；环境缺失问题单独记录，不用 mock/fake 掩盖。

## 实施顺序

1. 建立当前源码、配置、测试和运行依赖基线。
2. 修复注册租户、资源所有权和请求主体边界。
3. 修复 RabbitMQ/Feishu 启停控制与上传资源耗尽风险。
4. 修复迁移校验、健康检查和基础设施安全配置入口。
5. 修复 AI 取消/并发及资源生命周期问题。
6. 修复 Feishu、教学工作流、MCP、检索和查询性能问题。
7. 执行真实回归并生成报告。

## 验收门槛

- 未登录或错误租户不能读取、写入或同步其他租户资源。
- 后台开关关闭时无自定义 Rabbit consumer、scheduler 或外部同步任务启动。
- 迁移版本漂移会阻断启动，而不是静默忽略。
- 健康与就绪状态反映真实依赖。
- ZIP 和上传生命周期在边界、异常和重启场景下可控。
- 原有 capability token 关键词和协议不重新出现。
- 真实测试结果、失败原因和未完成项全部写入修复报告。
