可以收敛。原审计的 28 项可以合并为以下 12 类问题。

## 已关闭或明确排除

- Capability Token 全链路遗留：已删除，不再列为问题。
- `localPath` 路径限制：按你的要求保留，属于本地开发能力，不纳入修复清单。
- 限流值为 `0` 即无限制：已改为按用户主体、接口和租户限流；`0` 使用安全默认值。
- 前端 capability API、请求 Hash、旧审计代码：已删除。

## 当前剩余问题

### P0：必须优先处理

1. 用户注册仍可指定任意租户

公开注册接口仍接收 `tenantId`，攻击者可以自行注册到其他租户。

相关位置：

- `backend-java/src/main/java/com/doob/mathagent/auth/dto/RegisterRequest.java`
- `backend-java/src/main/java/com/doob/mathagent/auth/service/AuthService.java`
- `backend-java/src/main/java/com/doob/mathagent/auth/service/MyBatisLocalAccountStore.java`

应改为默认租户、邀请码或管理员审批决定租户归属。

2. 租户资源所有权仍存在缺口

教师资源测试仍发现共享资源的教师、学生、跨租户访问边界不完全正确，需要统一检查：

- 租户
- 用户主体
- 用户角色
- 资源所有者
- 资源共享范围
- 读写权限

3. RabbitMQ 消费者可能绕过全局关闭配置

全局配置为 `auto-startup: false`，但自定义监听器工厂没有统一设置 `autoStartup(false)`。

涉及：

- Agent Worker
- Lecture Task
- Teacher Source Sync

这会导致开发人员以为后台任务关闭，实际仍然消费消息、调用 AI 和写数据库。

4. Feishu 定时同步默认开启且空列表可能扫描全部目录

当前配置仍是：

- scheduler 默认开启
- `document-ids` 为空时代表全部已登记目录

会产生非预期的外部网络请求、文件下载、解析、向量重建和 AI 消耗。

5. 基础设施认证与凭证安全不足

仍存在：

- Redis 无认证
- RabbitMQ 使用 `guest:guest`
- RabbitMQ 管理端口暴露
- MySQL、Milvus、Worker、加密密钥等配置中存在硬编码安全凭证
- 本地配置与生产安全配置未彻底分离

6. 数据库迁移和启动校验不闭环

虽然已经补充 V29，但当前仍存在：

- 数据库迁移执行开关关闭
- 使用 `ignore-migration-patterns: versioned:missing`
- 允许数据库版本和源码迁移版本不一致启动

需要改为启动前强校验版本、Checksum 和迁移完整性。

## P1：高风险稳定性问题

7. 上传 ZIP 仍缺少完整压缩炸弹防护

普通上传已有总大小和文件数限制，但 ZIP 解压仍缺少：

- 单文件解压大小限制
- 压缩比限制
- 目录深度限制
- 解压异常后的统一清理
- 临时目录成功归档后的生命周期清理

相关文件：

- `backend-java/src/main/java/com/doob/mathagent/teacher/service/TeacherResourceUploadService.java`

8. 客户端可以伪造 IP 和设备标识

当前限流已经按登录用户主体执行，但仍需处理：

- 直接信任 `X-Forwarded-For`
- 直接信任 `X-Device-Id`
- 未配置可信代理链时可能绕过风控

登录用户限流主体已经完成；匿名请求因没有用户身份，仍会使用匿名主体、设备和连接地址作为兜底。

9. AI 请求取消和全局并发控制不完整

仍需统一覆盖：

- 学生 SSE 断开后的 AI 请求取消
- 教学工作流
- 学生解释
- 视觉入库
- MCP 调用
- Agent Worker

目前并发保护尚未证明所有入口都经过同一个 GPU/模型调度层，存在显存峰值和请求堆积风险。

10. 健康检查不能真实反映依赖状态

`/api/system/health` 仍返回固定 `UP`，不能反映：

- MySQL
- Redis
- RabbitMQ
- Milvus
- AI Worker
- Flyway 状态

应区分 liveness 和 readiness，并真实检查关键依赖。

11. 会话 Token 存储在前端 `localStorage`

如果前端出现 XSS，Token 可直接被读取。应改为 HttpOnly、Secure、SameSite Cookie，并补充 CSP 和输入输出安全策略。

## P2：功能与数据一致性问题

12. Feishu 同步状态机和资源恢复逻辑不一致

目前仍有：

- 重同步返回 `skipped_unchanged`，但测试和业务期望 `download_completed`
- 向量 readiness 状态不稳定
- 图片 manifest 与本地文件状态不一致
- 已下载文件恢复逻辑不完整
- 元数据存在但图片文件缺失时清理抛 `NoSuchFileException`
- 普通上传归档后临时文件长期保留

13. 教学工作流存在状态和输出异常

仍发现：

- 任务停留在 `CREATED`
- 部分任务进入 `FAILED`
- 讲义正文为空或只剩 `\vspace`
- AI Draft、模板上下文、教师版和学生版输出契约不一致
- 多 Agent 实际阶段数、Agent 顺序与协议测试预期不一致

14. MCP、知识图谱和工具发现契约不一致

仍存在：

- MCP graph spine 返回空节点或边
- MCP 多 Agent trace 顺序不稳定
- 工具发现列表与既有契约不一致
- 当前额外暴露教师资源和题库工具，需要统一协议版本和权限描述

15. 教师资源检索质量不稳定

题型过滤、否定语义、弱相关过滤和排序仍有失败，涉及：

- `TeacherResourceBlockSearchService`
- `TeacherResourceBlockSearchPolicy`
- RAG 候选召回与排序链路

16. SQL 安全规则仍未完全收敛

仍需逐项审查：

- MyBatis 注解 SQL
- `.apply`
- `.last`
- `inSql`
- 动态排序字段
- 动态表名或条件拼接

同时 SQL 安全契约文档存在相对路径缺失问题。

## 性能和架构问题

17. 查询存在全量加载

仍有：

- 题库全量加载后再 `limit`
- 学生记忆全量加载后再计算
- 教材 BM25 内存语料
- Milvus 使用 `FLAT`
- 缓存默认关闭

数据增长后会造成内存、GC、数据库传输和响应时间恶化。

18. 请求级线程池大量创建

多个教学、写作和 AI Gateway 路径仍然创建请求级线程池，需要统一为受控共享线程池，并补充：

- 队列上限
- 拒绝策略
- 超时
- 线程指标
- 任务取消
- GPU 并发指标

19. 两套讲义生成链路并存

`MultiAgentWritingService` 与 `TeachingWorkflowService` 存在重复的状态、并发、导出和错误处理逻辑，长期会导致行为分叉。

20. 核心类过大

主要包括：

- `TeachingWorkflowService`
- `TeachingWorkflowExecutionSupport`
- `MultiAgentWritingService`
- `App.tsx`
- `textbookApi.ts`

需要按权限、状态机、调度、导出、持久化、API Client 和 UI 页面拆分。

21. 部署环境耦合严重

仍存在：

- Windows 路径
- WSL 路径
- 容器路径
- MiKTeX 和字体路径
- 两套 RabbitMQ/Milvus 实例
- Dockerfile 复制固定 JAR

会导致本机、WSL、容器和部署环境行为不一致。

22. 测试环境和验收条件不完整

当前完整 Maven 测试仍有：

- 711 个测试执行
- 50 个失败
- 29 个错误
- 15 个跳过

主要集中在：

- 缺少 `python3`
- 缺少 XeLaTeX
- Feishu 同步契约
- 教学工作流输出
- 教师资源检索
- MCP 图谱与工具契约
- SQL 规则文档路径

## 最终阻断结论

当前真正需要优先收敛的是：

1. 注册租户和资源所有权隔离。
2. RabbitMQ、Feishu 后台任务的启动边界。
3. Redis、RabbitMQ 和源码凭证安全。
4. Flyway 迁移一致性。
5. 真实健康检查。
6. ZIP 上传与资源生命周期。
7. AI 取消和全局 GPU 并发。
8. Feishu 同步、教学工作流和 MCP 契约。
9. SQL 安全与查询性能。

工作区脏文件、`localPath`、本地 WSL 路径属于已知工作方式或治理事项，不再与产品缺陷混在一起。
