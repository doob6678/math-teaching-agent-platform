# 讲义 PDF 渲染开发规范（强制阅读）

凡修改讲义提示词、Markdown 转换、公式规范化、PDF 导出、页眉页脚、学生作答区、16:10 投影稿或验收脚本，必须先阅读本文件及 README 的“讲义与 PDF 不可违反的硬性要求”。这是发布契约，不是建议。

## 已验证的生成链路

`教材检索 + 已授权飞书资料检索` → `Luna Markdown` → `FormulaMarkupSanitizer` → `Markdown/LaTeX 转换` → Docker 内 `XeLaTeX + Noto CJK` → MCP Base64/SHA-256 → Windows Poppler 全页 PNG 与布局审计。

任何替代链路（截图公式、PDFBox 伪渲染、宿主机字体假设、只检查文本提取）都不能替代该验收。

## 不可修改的排版规则

1. 数学仅允许 `$...$` / `$$...$$`；分式必须为 `\\frac{分子}{分母}`，根式必须为 `\\sqrt{完整被开方内容}`。裸 `/`、`√`、裸 TeX 命令和未闭合定界符必须拒绝导出，不得猜测修复。唯一允许的定界符修复是导出边界对已观测的 `$$$left$$right$` 传输形态做确定性拼接；除此之外的混用定界符仍必须拒绝，并保留原始诊断。
2. 页眉、页脚、页码、配色、纸张尺寸和字体属于渲染器，不属于模型正文。三种版本均由 Docker 内的 Noto CJK 与 XeLaTeX 生成。
3. 教师版必须含教材章节、飞书可读来源和至少六道独立原题；学生版不得含答案、教师批注、trace、来源内部标识或 HTML。
4. 学生的计算、证明、画图和说明题使用真实垂直留白；仅单值填空使用短横线。富文本空 `div` 的 CSS 高度要转换为 LaTeX 垂直空间，禁止打印 HTML，也不得用横线替代大段作答区。
5. 16:10 仅一页、一个真实题目，题干是首个正文区块；从教师版抽取题干时必须按“问题/原题”语义匹配任意 Markdown 标题层级，不能使用方法提示句或 JSON 字段名。

## 每次修改后的真实验收

- 运行 Java 公式/导出单测；启动 Docker backend、ai-worker、MySQL、Redis、RabbitMQ、Milvus。
- 运行真实 Luna MCP/ReAct；记录每一条 HTTP 状态、模型请求、工具调用、阶段开始结束、token 与耗时。单次模型请求必须有独立硬超时，不能把全流程轮询超时用于模型调用。
- 经 MCP 导出教师、学生、16:10 三份 PDF，核对 MCP SHA-256 与本地字节哈希一致。
- 在 Windows 以 Poppler 渲染全部页面，运行布局审计，并人工查看至少教师公式页、学生留白页和 16:10 页。任何失败都必须保留证据目录并标记失败，不能称“验收完成”。
