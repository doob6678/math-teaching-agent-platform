# 高考 Canonical Corpus 精确去重与生产重建归档

## 适用范围

本归档只约束本目录 `output/math-paper-corpus/` 发布的 canonical 高考数学资料进入唯一生产 Milvus collection `gaokao_math` 的方式。

- 不新建按年份、模型、试卷类型拆分的 collection。
- 不按题干、答案、解析、关键词、知识点或语义相似度合并题目。
- 同一试卷的不同题号必须分别保留。
- 同一试卷同一题号只能有一条 `QUESTION` 向量记录。
- 题级图片只使用 manifest 绑定的 `figures/` 资产 ID；向量 metadata 不写文件路径、URL、Base64 或 LaTex 图片命令。

## 精确题目身份

每一道 canonical 题目的最终主键只依赖不可变原卷 SHA-256 与印刷题号：

```text
UUIDv5(URL, "question\n" + sourceSha256 + "\n" + numericQuestionNumber)
```

实现位置：`scripts/wsl/run_2024_luna_milvus_ingestion.py` 中的 `canonical_question_id(source_sha256, question_number)`。

这意味着以下变化不会改变题目主键：

- 页码和跨页范围；
- Terra 的文字细节；
- 答案和解析挂载；
- 题图资产；
- provider、embedding 批次或运行次数。

同一原卷、同一题号再次入库会得到相同 Milvus 主键。Milvus 的 upsert 只能覆盖该行，不能增加一条新题目行。

## 入库前拒绝规则

生产重建接口读取每份 `source-manifest.json`、`document.md` 与 `questions/*.md`，在调用 embedding 前必须通过：

1. 所有发布 Markdown 的 SHA-256 与 manifest 一致；
2. manifest 中 `questionId` 等于上述稳定主键；
3. `(sourceFile, questionNumber)` 在整个 corpus 中唯一；
4. 本批 canonical corpus 固定为 12 份 manifest、250 道题、12 条全文档，共 262 条 Milvus 实体；
5. 任何不符合这些条件的输入直接失败，不能开始 production replacement。

因此，同一 canonical corpus 内的重复题不会被静默接受，也不是在召回窗口中临时折叠。

## 生产替换接口

接口文件：

```text
scripts/wsl/rebuild_gaokao_from_canonical_corpus.py
```

只读校验与真实 GPU embedding：

```powershell
wsl.exe -d Ubuntu -- bash -lc "cd /mnt/c/Users/doob/Desktop/code/dev/math_agent_rag && python3 scripts/wsl/rebuild_gaokao_from_canonical_corpus.py"
```

显式完整生产替换：

```powershell
wsl.exe -d Ubuntu -- bash -lc "cd /mnt/c/Users/doob/Desktop/code/dev/math_agent_rag && python3 scripts/wsl/rebuild_gaokao_from_canonical_corpus.py --replace-production"
```

`--replace-production` 的严格顺序：

1. 校验所有 canonical Markdown、manifest 和稳定 ID；
2. 用真实 `local_bge_embedding` 预先完成 262 条 512 维 embedding；
3. 只有前两步全部成功后，drop 唯一 collection `gaokao_math`；
4. 重建固定 schema、COSINE/FLAT vector index 并 load；
5. 按每批 100 条 upsert，最后 flush 一次；
6. 使用 12 个 canonical 来源的服务器端过滤 count 复核总数为 262；
7. 固定查询 `抛物线 焦点 准线`，`limit=10`，对原始命中按 `(sourceFile, questionNumber)` 检查重复；任何重复会使接口失败。

该接口不读取 PDF、不调用视觉模型、不访问飞书链路、不使用其它 Milvus collection，也不把全量 collection 加载进 Python 内存。
