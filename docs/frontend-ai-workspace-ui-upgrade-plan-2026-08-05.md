# AI 工作台 UI 全面升级方案

## 结论

当前前端不是能力不足，而是同一类 AI 运行信息被拆成多套卡片、`details` 和状态样式。项目已经真实接入了 SSE 讲题流、RAG 证据、Agent 运行计划/轨迹、多 Agent 工作流、讲义版本、PDF Canvas 预览和人工审校。升级应保留这些真实后端契约，建立一套统一的 AI 工作台界面层，而不是替换为另一个 Agent 框架。

最终视觉方向定为“浅色专业工作台”：纸白阅读面、低饱和青绿作为主强调色、蓝色只用于可操作链接、橙色只用于提醒、红色只用于失败。禁止大面积深色容器、黑色实心操作按钮、黑色边框、装饰性径向光晕和叠层卡片。

## 已有页面与真实功能

### 审计基数（代码实测）

- 路由级页面：9 个，`dashboard`、`search`、`teaching`、`agents`、`streaming`、`knowledge`、`mcp`、`settings`、`login`。
- 面板组件模块：14 个；共享 AI 运行信息主要在讲题、Agent、讲义、检索、MCP 五条链路中出现。
- 真实可恢复/可审计对象：讲题 SSE 会话、教材检索 query、Agent Trace、多 Agent workflow、讲义 task/version/PDF、MCP key/connection test。它们均由后端返回或推进，前端不生成替代记录。
- 本期不采用任何新的 Agent Runtime 或全量 UI 框架。CopilotKit、Elysia、UltraRAG 和 n8n 只提供信息架构参考；现有 React + CSS + Java/Python SSE/MCP 契约保持不变。

### 页面与优先级

| 页面 | 真实功能 | 当前主要问题 | 升级目标 |
| --- | --- | --- | --- |
| 工作台 | 学习画像、教材资源、任务入口 | 入口与状态曾混在数据卡片中 | 以当前任务为主线，保留角色化入口和连续状态 |
| 教材检索 | 混合检索、公式图、教材范围、审计、命中证据 | 检索阶段、审计、命中证据层级相近 | 形成“查询 -> 过程 -> 证据”的单一阅读链路 |
| AI 讲题 | 图像上传、SSE 文本/思考、连续追问、来源 | 讲解、过程、来源三套盒子；折叠行为不一致 | 主回答优先，右侧/抽屉展示真实运行和证据 |
| AI 控制台 | 模型健康、运行预案、真实调用、Trace、多 Agent | 配置、计划、调用、过程流以普通卡片堆叠 | 固定的控制台三栏和可审计运行时间线 |
| 讲义生成 | 历史、模板、检索、生成、版本、PDF、人工审校 | 深色悬浮控件、渐变背景、过大圆角与预览并存 | 左任务/中编辑/右预览的文档工作台 |
| 知识库 | 图谱、知识点、题库、教师资料 | 管理型页面沿用普通卡片壳 | 表格/列表优先，二级信息放抽屉或折叠区 |
| MCP 接入 | 身份边界、Key、配置、连通性 | 安全说明与配置详情的折叠样式不统一 | 安全状态条 + 配置面板 + 审计详情 |
| 系统设置 | 账号、服务配置、教师账号 | 与 AI 运行界面视觉断裂 | 使用相同的表单密度、状态徽标和帮助面板 |
| 登录 | 后端账号会话 | 与工作台品牌关系弱 | 使用简洁入口，不使用营销式大卡片 |

## 代码审计发现

1. `frontend/src/styles.css` 已积累为约一万行，并存基础卡片、讲题页专用覆盖、讲义页专用覆盖；同一个“运行步骤”在 `teaching-*`、`agent-process-*`、`review-process-*`、`tool-decision-*` 中有不同的边框、间距、圆角和状态颜色。
2. `TeachingConversationPanel.tsx` 已真实展示流式文本、工作流阶段、题图识别和来源，但最终回答的多个 `teaching-response-card` 与证据检查器都像独立卡片，阅读焦点被切碎。
3. `AgentPanels.tsx` 已有准确的计划、工具范围、阶段耗时、诊断事件和可恢复 Trace；但目前每一个事件都使用裸 `details`，无法快速区分“思考/检索/工具调用/恢复/结果”。
4. `MultiAgentWritingPanel.tsx` 和 `HandoutWorkspacePreviewPanel.tsx` 已有完整工作流和文档交付能力，却同时使用深色工具按钮、重渐变容器、超大圆角及多层卡片，文档预览缺少稳定的编辑器/预览层级。
5. 现有 CSS 中 `--navy` 被用于顶部导航、头像、多个主按钮和讲义控制器。它应只作为文本层级颜色，不再作为大面积视觉背景或主按钮底色。
6. 各页面目前使用超过二十个原生 `details`。原生语义正确，应保留，但必须由一个统一的可访问“运行明细折叠项”组件承载，避免不同页面的箭头、边框、默认展开状态和移动端行为不一致。

## 参考项目的可采纳部分

| 参考 | 采用的模式 | 不直接采用的部分 |
| --- | --- | --- |
| CopilotKit | 对话主区 + Agent 状态区；生成式 UI 仅渲染受控组件；工具状态、人工审批、共享状态 | 不引入其 Runtime 或预置聊天组件。当前 Java/Python 后端与 SSE/MCP 已经是实际运行链路，强行接入会重复会话、鉴权和流协议 |
| Weaviate Elysia | 决策步骤可视化、检索条件/命中证据可追溯、时间线表达 | 不复制深色玻璃态；教育讲义需要长时间阅读和打印预览，浅色高对比更适合 |
| UltraRAG | 对话与推理分区、来源与 Chunk 同步、文件处理状态 | 不引入 YAML/拖拽运行时；本项目的工作流已由后端持久化并可恢复 |
| n8n Agent UI | 紧凑角色切换、工具消息嵌入对话、即时状态反馈 | 不使用纯静态 Demo 风格；必须保留权限、租户和证据审计边界 |
| 企业 Agent UX 模式 | 可观察性、审批入口、失败恢复、权限显示 | 不展示模型原始思维链；只展示后端已产出的工作阶段、工具摘要、证据和诊断事件 |

### 浏览器核验记录

- 通过真实 Chrome 打开 [CopilotKit 公开首页](https://www.copilotkit.ai/) 后，可见信息架构把 Agent runtime、终端 surface、预制或 headless chat、生成式 UI、人工审批、前端工具和双向共享状态分别呈现；页面还将一次交互组织为 `user request -> state delta -> tool call -> UI render -> human approval -> outcome` 的事实事件链。
- 本项目采纳的是该事件链的可观察性，而不是其运行时：后端既有 SSE、MCP、权限、持久化 Trace 和讲义任务仍是唯一事实来源。前端将其投射为运行记录、证据栏、版本审校和人工决策面板。
- 本次浏览器会话访问 [Elysia 源码](https://github.com/weaviate/elysia) 时出现 `ERR_CONNECTION_TIMED_OUT`，因此没有据此扩展任何依赖或作出未验证的源码结论；Elysia、UltraRAG 和 n8n 的设计取舍以上述已有项目审计为准。

## 依赖取舍

### 本期不新增

- `@copilotkit/react-ui` / CopilotKit Runtime：不适合作为纯视觉替换，会和现有 `/api`、SSE、MCP、会话鉴权和可恢复任务重复。
- Tailwind、shadcn 整体引入：现有项目使用单一 CSS 文件，整套迁移只会扩大风险，不能解决运行态信息结构问题。
- Framer Motion：界面不需要重动画；状态变化使用 CSS 的短过渡并遵守 `prefers-reduced-motion` 即可。

### 按需引入

- `react-resizable-panels`：仅在讲题三栏、Agent 控制台和讲义三栏上线可拖动分栏时引入；它解决真实工作台的空间分配，不参与视觉系统。
- `@tanstack/react-virtual`：仅在 Trace、长历史、题库/资源列表达到大量真实记录后引入，避免在没有性能证据时增加复杂度。
- 不需要图表库。当前数据更适合进度条、时间线和表格，不能为了“高级感”堆图表。

## 统一设计规范

### 空间与边框

- 只使用 `4/8/12/16/24/32` 六级间距变量；组件内部默认 `12`，区块间默认 `24`。
- 工具面、列表项、折叠项圆角统一为 `8px`；PDF 纸张保持 `4px`；不再使用 `18/20/28px` 的装饰性大圆角。
- 默认边框使用低对比中性线；仅在 hover、focus 或状态异常时使用状态边框。不可再给每层容器加边框和阴影。
- 主按钮采用青绿实色或浅色描边，文字深色；危险操作才使用红色。深色只留给正文文本和小型代码块。

### 运行信息模型

所有 AI 链路都归到四种语义单元，组件名与样式必须共用：

1. `AIResponseSurface`：用户可直接阅读的回答、讲义正文或最终结果。无外层卡片套卡片。
2. `AIRunTimeline`：真实阶段、工具调用、检索、恢复、失败。每条有图标、状态、耗时、摘要；可展开安全详情。
3. `EvidenceRail`：来源标题、片段、来源类型、相关度、原文链接。按检索阶段归属，不把文件路径作为主内容。
4. `HumanDecisionPanel`：审批、版本选择、人工反馈、导出动作。与 AI 自动过程明确分隔。

### 思考与调用的安全边界

- “思考展示”在本项目中指可审计的执行过程，不是展示模型原始 chain-of-thought。讲题 SSE 的后端事件只对前端发出已清洗的回答增量、结构化讲解卡片、工作流阶段、耗时和来源；`aiReasoningDelta` 在当前学生讲题控制器中明确保持为空。
- UI 的“执行与证据”“检索运行记录”和 Agent Trace 因此只显示后端返回的阶段标题、已授权工具范围、受控调用参数摘要、命中来源、恢复状态与耗时。原始 prompt、模型 reasoning、token/debug JSON 和未审计路径不能进入折叠面板。
- 这既保留 CopilotKit/Elysia 风格的可观察性，也符合教育产品的可解释性与数据边界：用户能核对“做了什么、用了什么资料、是否完成”，但不会看到不可验证的内部思维文本。

### 页面布局

- 讲题桌面：历史抽屉 `240px`（按需展开）+ 回答主列 `minmax(560px, 760px)` + 运行/证据列 `300px`；窄屏将右栏变为底部抽屉。
- AI 控制台桌面：配置 `300px` + 当前运行 `minmax(420px, 1fr)` + Trace `360px`；Trace 不是普通页面底部卡片。
- 讲义桌面：任务历史 `248px` + 输入/过程 `minmax(420px, 0.8fr)` + PDF/版本预览 `minmax(520px, 1.2fr)`；平板隐藏历史，手机将预览改为独立标签页。
- 教材检索：查询条固定在顶部，阶段摘要紧随查询结果，命中证据使用一条主列表，不使用“审计卡片 + 命中卡片 + 卡片内卡片”。

### 折叠与可访问性

- 思考和执行记录默认折叠，标题固定为“运行记录”，显示真实阶段数、运行状态和总耗时。
- 检索步骤才允许展开来源；生成、解析、存储等步骤只展示后端返回的摘要，绝不伪造或泄露内部推理。
- `summary` 必须具有 44px 可点击高度、旋转箭头、`[open]` 状态、键盘焦点环和移动端不溢出的两行布局。
- 图标按钮必须保留 `aria-label` 和 hover tooltip；窄屏不只显示无说明图标。

## 实施顺序

### 第一阶段：公共基座和讲题链路

1. 将色板、间距、圆角、边框、阴影收敛成语义 token，移除讲义页的径向背景和深色悬浮控制器。
2. 新建 `AIRunTimeline` 和 `EvidenceRail`，替换讲题页的流式阶段、最终执行记录、来源项。
3. 把讲题最终回答改为连续阅读面；执行与证据成为稳定右栏，移动端为底部折叠面板。
4. 使用真实 SSE、图像识别、来源和错误状态做桌面/手机浏览器验收。

### 第二阶段：Agent 控制台和多 Agent 工作流

1. 将 `AgentPlanPanel`、`AgentTracePanel`、`MultiAgentWritingPanel` 接到同一时间线组件。
2. 计划、工具授权、模型用量用紧凑状态条展示；调用详情由时间线按阶段展开。
3. 多 Agent 流程展示角色、当前阶段、产物和恢复动作，不再使用层层嵌套的普通卡片。

### 第三阶段：讲义工作台和检索

1. 使用稳定三栏和 `react-resizable-panels`（若实际需要拖拽）重排讲义历史、输入/过程和 PDF 预览。
2. 统一版本切换、导出、人工审校和 PDF 工具栏，纸张预览始终是最大视觉对象。
3. 重构检索结果为查询状态 -> 运行阶段 -> 证据列表，审计号退到详情区。

### 第四阶段：管理页和回归

1. 知识库、MCP、设置使用相同的表单/列表/状态面，移除遗留大卡片壳。
2. 用真实登录账号对每一个角色、真实任务历史、真实 PDF 页面进行桌面与手机截图检查。
3. 验证键盘操作、焦点、长文本、失败/恢复状态、PDF Canvas 非空和页面不重叠。

## 本次已经完成的改动

工作台已调整为角色化主操作、可扫描的真实工作流入口、教材资源状态和学习概览四个层次，未改变 API、鉴权或生成流程。

讲题页已经把最终回答收敛为连续阅读面，检索来源和执行阶段留在独立的证据栏；流式阶段、题图识别和 SSE 文本仍只消费后端事件。Agent Trace 已由聊天式气泡收敛为状态节点时间线，工具范围、证据、模型用量和恢复诊断仍是可展开的真实记录。

讲义页已经重排为桌面三栏：历史、编写协作、版本/PDF 审校；在较窄桌面收敛为双栏并让预览全宽，移动端改为单列。右侧 PDF Canvas 仅在后端返回的 `taskId + version + PDF 字节 + 元数据` 匹配时显示，避免版本切换后展示旧文档。全页的讲义控制器、版本切换和 PDF 工具栏已统一为浅色 `8px` 工具面和青绿强调色。

教材检索已经改为左侧可固定的查询控制、右侧证据阅读面；检索阶段、审计追踪号和后端审计详情放入同一个“检索运行记录”折叠项，命中证据不会再被审计卡片抢占阅读焦点。知识库题库页已改为左侧录入/查询、右侧主干关系和题库结果，MCP 与系统设置则复用低边框 `8px` 工具面。上述改动不增加前端身份参数、虚拟任务或模拟运行记录。

旧讲义协作组件继续沿用 `teaching-*` 结构，但已加上受控的浅色兼容层：任务节点、证据、流式状态、空状态、输入区和提交动作都不能回退到黑色卡片、白色正文或大圆角。错误状态仍使用红色语义，真实任务/证据/版本数据不在前端重新解释或伪造。

讲题、检索、Agent、MCP、教师资源和审校中保留的原生 `details` 折叠项已收敛为同一交互合同：统一 `44px` 摘要点击区、低对比边框、展开分隔线、可见焦点和 CSS 开合指示。该规则不改变后端返回内容或默认展开状态；题图识别、来源、运行阶段和配置 JSON 仍只在用户主动展开后展示。讲题用户气泡、状态面、输入区、上传条和历史项也已压缩到 `8px` 工具圆角，连续答案正文保持无卡片圆角。

讲义三栏中仍由当前页面调用的“协作卡片流”已从旧的渐变、重阴影和 `12-16px` 大圆角改为低边框 `8px` 阅读面。卡片、步骤、标签和版本摘要使用工作台色板；只有真实 PDF 页面保持纸张投影，以区分可打印文档与周边操作界面。
