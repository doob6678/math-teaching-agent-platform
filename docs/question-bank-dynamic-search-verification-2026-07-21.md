# 题库动态检索验收记录（2026-07-21）

## 真实环境

- 后端：`http://127.0.0.1:8080`，使用管理员账号登录后调用接口。
- 数据源：MySQL 中的真实题库记录；没有注入测试数据。
- 检索排序：题库候选先经过主题边界过滤，再使用既有 `VectorIndexService` 的 BGE reranker；worker 不可用时保留真实候选并记录告警，不伪造分数。
- 前端：题库请求上限改为 500 条后再进行本地分页；查询开始和失败都会清空旧的题目、知识点、关系和图谱状态，避免上一轮结果造成“写死/假数据”错觉。

## 接口实测

登录后调用 `/api/question-bank/items?query=&limit=500`：

| 年份 | 记录数 |
| --- | ---: |
| 2022 | 163 |
| 2023 | 140 |
| 2024 | 99 |
| 合计 | 419 |

主题检索：

| 查询 | 返回 | 说明 |
| --- | ---: | --- |
| `二次函数` | 2 | 2022 函数变换、2022 函数综合题；严格排除统计、立体几何、双曲线等仅因 OCR 含 `x²` 的记录 |
| `隐零点` | 3 | 返回真实高考题记录 |
| `双曲线` | 25 | 返回 2022--2024 双曲线题及解析记录 |

“二次函数”过滤兼容 OCR 丢失 `f(x)` 或括号的情况：只要同时出现函数语义和二次项（`x^2`、`x²`、`x2`），且没有三次函数或圆锥曲线特征，即可进入 BGE 重排。

## 代码与测试

- `KnowledgeQuestionBankService`：动态候选上限 500、严格主题过滤、生产 BGE reranker、worker 异常保留真实候选并记录日志。
- `QuestionBankSearchText`：集中维护具体主题词，避免 SQL 关键词扩张跨主题污染。
- `App.tsx`、`KnowledgeWorkspace.tsx`、`textbookApi.ts`：清理旧查询状态并统一 500 条候选后本地分页。
- 后端：`mvn -q -DskipTests compile` 通过。
- 后端题库测试：`KnowledgeQuestionBankServiceTest` 通过，包含 OCR 二次项回归用例。
- 前端：题库/API 测试 2 个文件、59 条用例通过；`npm run build` 通过。

## 边界说明

“二次函数”不是按年份强行返回全部高考题，而是按题目实际内容返回相关函数题；圆、抛物线、双曲线等含 `x²` 但不属于二次函数的题会被排除。需要浏览全部题目时使用空查询并通过前端分页查看 419 条真实记录。

## 2026-07-21 权限回归复验

下午重启后端并以真实 `admin/school-a` 会话重新请求同一接口，当前库返回 429 条 active 记录。题目标题中可识别年份的记录为：2022 年 171 条、2023 年 140 条、2024 年 99 条；其余记录来自教师资料导入和其他年份。由于本次同步/去重状态与上午快照不同，页面应以接口实时返回总数为准，不再显示固定的 419。

此前学生端出现 `403 Endpoint requires subject type in [teacher, admin]`，原因是只读 GET 与教师写入 POST 共用了同一条管理员访问规则。现已将 `/api/question-bank/items` 的接口层放宽到已登录学生/教师/管理员，写入仍由 capability token 和服务层教师/管理员校验保护；题库查询的 MyBatis 可见性过滤继续限制学生只能看到 `MATH_VIP`、`PUBLIC_TEXTBOOK`，教师私有题仅对所属教师可见。
