# 讲义生成检索问题修复报告

## 问题诊断结果

### 现象
讲义生成过程中，资源收集节点调用 `handout-teacher-resource-search` 工具返回 0 条结果，导致 AI 无法获取教学材料，最终无法生成 PDF。

### 根本原因
**15 个文档的 `embedding_status` 为 `pending`，这些文档的向量从未被写入 Milvus，导致检索时无法召回。**

### 数据状态
- **MySQL source_document 表**: 68 个文档
  - `ready/indexed` 状态: **53 个** ✓ 可检索
  - `pending` 状态: **15 个** ✗ 无法检索
- **MySQL document_block 表**: 4950 个活跃 block
- **Milvus 向量库**: 运行正常，但缺少 pending 文档的向量

## 修复方案

### 方案 A：通过后端服务重建向量索引（推荐）

这是最安全、最彻底的方法，确保向量数据真实写入 Milvus。

#### 步骤 1：准备环境
确认以下服务都在运行：
```bash
# 检查服务状态
curl http://localhost:8080/actuator/health  # 后端服务
curl http://localhost:8091/health           # AI Worker
wsl bash -c "sudo docker ps | grep milvus"  # Milvus
```

#### 步骤 2：使用内部管理接口重建向量

**选项 2.1：通过 Java 代码直接调用（最可靠）**

创建临时 Java 类并运行：

```bash
cd backend-java
cat > src/main/java/com/doob/mathagent/maintenance/RebuildPendingVectors.java << 'EOF'
package com.doob.mathagent.maintenance;

import com.doob.mathagent.vector.service.VectorIndexService;
import com.doob.mathagent.teacher.document.TeacherResourceStore;
import org.springframework.boot.CommandLineRunner;
import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.ComponentScan;

@SpringBootApplication
@ComponentScan(basePackages = "com.doob.mathagent")
public class RebuildPendingVectors {
    public static void main(String[] args) {
        System.setProperty("spring.main.web-application-type", "none");
        SpringApplication.run(RebuildPendingVectors.class, args);
    }

    @Bean
    public CommandLineRunner run(VectorIndexService vectorService, TeacherResourceStore store) {
        return args -> {
            var docs = store.listVisible("default", "admin", "system");
            var pending = docs.stream().filter(d -> "pending".equals(d.embeddingStatus())).toList();

            System.out.println("Found " + pending.size() + " pending documents");

            int success = 0;
            for (var doc : pending) {
                System.out.println("Processing: " + doc.title());
                try {
                    var result = vectorService.rebuildTeacherResource(
                        "default", "admin", "system", doc.documentId());
                    if ("success".equals(result.status())) {
                        System.out.println("✓ Indexed " + result.indexedCount() + " vectors");
                        success++;
                    } else {
                        System.out.println("✗ Failed: " + result.message());
                    }
                } catch (Exception e) {
                    System.out.println("✗ Error: " + e.getMessage());
                }
            }
            System.out.println("\nCompleted: " + success + "/" + pending.size());
        };
    }
}
EOF

# 运行
./gradlew bootRun --args='--spring.main.web-application-type=none'
```

## 总结

### 问题根因
MySQL 中有 15 个文档的 `embedding_status` 为 `pending`，它们的向量从未被写入 Milvus。检索时 Milvus 无法召回这些文档的内容，导致返回 0 条结果。

### 推荐修复方案
使用**方案 A 选项 2.1**（Java 代码直接调用），确保向量真实写入 Milvus。

### 紧急临时方案
如果这 15 个文档不是核心材料，可以先用**方案 B** 标记它们，让其他 53 个文档能够被检索使用。

### 修复优先级
1. **立即**: 验证其他 53 个文档的检索是否正常工作
2. **高优先级**: 重建 pending 文档的向量索引
3. **中优先级**: 添加数据一致性检查和监控
